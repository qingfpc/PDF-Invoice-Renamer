# PDF Invoice Helper: rename invoices and merge pages onto A4

Read dates, amounts, invoice numbers, and buyer and seller names from PDF electronic invoices. Rename files using your selected format, then arrange two PDF pages vertically on each A4 sheet. Run the combined application or either standalone tool.

This README describes the current `main` source. Published EXE behavior follows its [release notes](https://github.com/qingfpc/PDF-Invoice-Renamer/releases). Build from source to use the features documented here.

The current stable version is [v3.0.0](https://github.com/qingfpc/PDF-Invoice-Renamer/releases/tag/v3.0.0). See the [release notes](docs/releases/v3.0.0.md) for changes and Python API migration details.

## Features and processing scope

Processing follows these rules:

- **Rename validation**: Requires a recognized invoice number and the fields used by your naming format. Unrecognized documents or missing fields preserve the original name and report a reason
- **Amounts**: Supports negative values and thousands separators, then formats names with two decimal places, such as `1,234.56` becoming `1234.56`
- **Repeat runs**: Adds suffixes for name collisions and preserves names that already match. Existing output files are never overwritten
- **A4 layout**: Processes every PDF page, placing two source pages on each A4 sheet. An odd final page leaves the lower half empty
- **Stamps and text**: Both merger entry points render visible pages and annotations at 216 DPI. Output pages are images, so text cannot be selected or searched. Use them for printing and retain original invoices for archiving
- **Failure reporting**: Partial failures produce the successful pages and list omissions. No usable pages means no blank output file

Only the selected folder is scanned, without subfolders; both `.pdf` and `.PDF` are accepted. Renaming reads invoice information from the first page. Merging processes every page and skips bundles previously generated by this tool.

**Merging does not check whether a PDF is an invoice.** Readable PDFs remain eligible even if renaming failed. Put the files you want to print in a separate folder.

## Use the Windows EXEs

Download the EXEs from the [releases page](https://github.com/qingfpc/PDF-Invoice-Renamer/releases/latest). The v3.0.0 attachments and current source builds use the names below. Check the attached filenames for other versions:

| Application | Purpose |
| --- | --- |
| `InvoiceHelper_AllInOne.exe` | Choose whether to rename and whether to merge |
| `InvoiceRenamer_Only.exe` | Extract invoice fields and rename files |
| `InvoiceMerger_Only.exe` | Merge PDF pages, including image-only scans |

Double-click the application, then enter or drag in your folder path. For merging, enter an output directory or a full PDF filename. Press Enter to use the input folder. Missing output directories are created, and existing output names receive a numeric suffix.

## Run from source

Validated on Windows 11 with 64-bit Python 3.12. The `python` command below must select Python 3.12; check with `python --version`. For another installation or a Conda environment, use its interpreter instead.

Clone the repository, create a project environment, and install runtime dependencies:

```powershell
git clone https://github.com/qingfpc/PDF-Invoice-Renamer.git
cd PDF-Invoice-Renamer
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Run the combined application from the repository root:

```powershell
.\.venv\Scripts\python.exe invoiceMaster.py
```

Use these commands for the standalone tools:

```powershell
.\.venv\Scripts\python.exe invoiceTool.py
.\.venv\Scripts\python.exe mergeInvoices.py
```

## Choose a naming format

The interactive tools offer four formats. Shared presets are defined in `PRESET_FORMATS` in [invoice_core.py](invoice_core.py):

| Option | Format | Example filename |
| --- | --- | --- |
| 1 | `{date}_{seller}_{amount}` | `20231225_JD_299.00.pdf` |
| 2 | `{seller}_{date}_{amount}` | `JD_20231225_299.00.pdf` |
| 3 | `{code}_{number}` | `033001234567_12345678.pdf` |
| 4 | `{amount}_{seller}` | `299.00_JD.pdf` |

Custom formats accept these fields:

| Field | Meaning |
| --- | --- |
| `{date}` | Invoice date as `YYYYMMDD` |
| `{seller}` | Seller name |
| `{buyer}` | Buyer name |
| `{amount}` | Amount with two decimal places, including negative values |
| `{code}` | A 10-digit or 12-digit invoice code |
| `{number}` | An 8-digit or 20-digit invoice number |

Pass a folder and custom format to rename by invoice number and amount:

```powershell
.\.venv\Scripts\python.exe renameInvoices.py "D:\Invoices" `
    --format "{number}_{amount}"
```

Full-digital invoices may have no invoice code. Option 3 then preserves the original name and reports missing `code`. Choose a format whose fields are present, or use the command above with `{number}`.

## Run tests

Install development dependencies from the repository root before running tests. `requirements.txt` alone does not install the PDF generation library used by tests:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Tests generate temporary PDFs and perform actual parsing, renaming, rendering, merging, and CLI process execution. Personal invoices are untouched. Coverage includes amounts, missing fields, collisions, repeat runs, multiple pages, rotation, annotations, scans, corrupt files, and encrypted PDFs. Generated samples do not establish compatibility with every real invoice template.

## Build and verify EXEs

After installing development dependencies, run the build script from the repository root using PowerShell 7 (`pwsh`):

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
pwsh -NoLogo -NoProfile -File .\build.ps1
```

The script builds the three EXEs listed above in `dist/`. Git ignores `build/`, `dist/`, and `.venv/`. Local builds do not automatically update GitHub release attachments.

Run the same interactive tests against the built EXEs:

```powershell
$env:INVOICE_TEST_EXE_DIR = (Join-Path (Get-Location) 'dist')
try {
    .\.venv\Scripts\python.exe -m unittest tests.test_cli -v
} finally {
    Remove-Item Env:\INVOICE_TEST_EXE_DIR -ErrorAction SilentlyContinue
}
```

## Modules and return values

The code is organized by responsibility:

| File | Responsibility |
| --- | --- |
| `invoiceMaster.py` | Combined interactive application |
| `invoiceTool.py` | Standalone interactive renamer |
| `mergeInvoices.py` | Standalone interactive merger |
| `renameInvoices.py` | Reusable `InvoiceRenamer` class and custom-format CLI |
| `invoice_core.py` | Shared parsing, validation, path cleanup, and renaming |
| `invoice_merge.py` | Shared page layout, output protection, and failure reports |
| `build.ps1` | Build the three Windows EXEs |
| `tests/` | PDF and CLI regression tests |
| `requirements.txt` | Runtime dependencies |
| `requirements-dev.txt` | Test and build dependencies |
| `constraints.txt` | Validated Windows / Python 3.12 dependency versions |

`extract_invoice_data()` returns `None` for unrecognized documents. Missing fields on recognized invoices are also `None`, rather than placeholder strings or fabricated zero amounts. Calling `read_invoice_data()` directly raises an exception when recognition fails. Check required fields before formatting filenames.

`rename_invoices()` and `InvoiceRenamer.rename()` return per-file results with a `renamed`, `skipped`, or `failed` status. `merge_pdf_files()` returns source and merged page counts, the output path, failures, and skipped files. Its `output` is `None` when no pages are usable.

## Known limitations

Consider these limits when selecting files and checking results:

- Renaming targets standard Chinese electronic invoices and requires an 8-digit or 20-digit invoice number. Nonstandard receipts may be unrecognized
- There is no optical character recognition (OCR). Scanned images cannot be renamed from extracted fields, but can be merged for printing
- Buyer and seller names still depend on labels and layout order. Check recognition results for unusual templates
- Renaming uses the first page of a multi-page file; merging retains every readable page
- Encrypted PDFs must be decrypted first. Corrupt files are reported as failures
